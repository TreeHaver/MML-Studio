# Character limits and multipart MS2MML export

Export > Character limit is a saved application preference, defaulting to 10,000. Positive whole numbers are accepted; project JSON remains version 2. The limit counts the combined raw MML characters in all channels of one instrument (ASCII bytes), excluding XML markup. It never restricts import, editing, saving projects or raw MML generation.

The active musical instrument shows a red timeline line at its first planned sheet boundary when its MML reaches/exceeds the limit. Below the limit there is no line. The line uses current notes, preset mapping and global tempo events, even if the instrument's manual MML snapshot is paused. It updates on edits, addition/deletion, undo/redo, instrument selection and limit changes. Scrolling/zoom moves the cached marker without replanning unchanged data. Instructions lanes have no sheet line. A limit too small for synchronized notes/controller commands shows a red warning at the start.

Oversized export asks “Do you still wish to export?” with “Yes, and in a single file”, “Yes, in parts”, and “No”. Escape cancels. Single-file export keeps the entire instrument; parts use numbered filenames. Every part is generated and checked against the chosen limit before save dialogs begin. Canceling a save dialog stops subsequent saves and reports how many files were already saved. All-instrument export applies the same choice to each oversized instrument before starting saves; different instruments have independent sheet boundaries.

Each part covers one shared [start, end) interval across its channels. Notes crossing that interval are clipped for export and their remainder starts at time zero in the next part. Original project notes are unchanged. Each channel starts with current global tempo and emits octave/volume for its first note; carried notes retain their resolved source volume. Tempo changes inside each interval propagate to all channels. Trailing rests pad shorter channels to the common boundary; leading silence is retained. These rests and controller commands count toward the limit. Separate files retrigger continued notes on playback; ties cannot span independent files.

The planner searches for a verified fitting time, then prefers a clean boundary within a quarter note (32 model units) before it where no note is sounding across the cut. If none fits, it divides held notes. Because duration compression makes character counts non-monotonic, search checks nearby integer boundaries as well; it is conservative, not an optimal packing/shortest-string algorithm. Each emitted part is independently size-checked and makes positive progress. If the chosen limit cannot accommodate the next synchronized notes and controller commands, export stops with an explanation instead of truncating or producing oversized parts.
