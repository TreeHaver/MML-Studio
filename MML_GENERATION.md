# MML generation

Each instrument has an exact Character count (UTF-8 bytes), channel count, Real time updating checkbox, Update MML button and Open MML button. Real time updating defaults on and updates during note creation, movement, resizing, inspector edits, deletion and undo/redo. Turning it off retains the generated snapshot; edits mark it Out of date. Update MML regenerates that instrument once. Undo/redo preserves the preference; New/Open/import reset it. Selection, scrolling and mute/solo do not regenerate unchanged strings. No generated strings are saved in version-2 JSON.

Open MML opens a separate, non-modal native window that remains usable alongside the editor. Tabs show per-channel byte counts; Copy to clipboard copies exactly the selected raw string, without a wrapper, whitespace or newline. Instrument totals sum those strings only. All emitted syntax is ASCII, so string length equals UTF-8 byte length. The native window follows the opened instrument, clamps the selected tab when channels disappear, and clears when the project is replaced. A paused snapshot remains visibly Out of date until refreshed.

Overlapping notes are partitioned into the minimum number of monophonic channels using an end-time heap. Channels start at song time zero and use rests for gaps. More than ten channels produces a warning without truncation. Splitting is for overlapping voices, not a per-channel byte cap: the separate sheet planner applies the configurable instrument character limit during file export (see SHEET_LIMITS.md).

The compiler emits explicit note lengths, octave and inherited V instructions. Arbitrary positive integer model durations remain exact through dotted notes and ties, including 5/7/11-unit durations and durations longer than a whole note. Using conventional denominators as a decomposition does not restrict stored durations or imply that MS2 forbids other denominators. Tempo changes from all instruments, including silent Instructions and muted lanes, are repeated in each musical channel through its final note. Rests and held notes are split at tempo boundaries; held fragments are tied. Instructions never become sounding notes or consume a generated musical channel.

Standard Drum Kit and out-of-range tempo/pitch values produce compatibility warnings. Source values are retained, not clamped; such warned strings need resolution before use in MS2. Program choice remains external to raw MML. Empty instruments produce zero channels and zero bytes. This is an exact serializer, not a shortest-string optimizer ; sheet planning is implemented separately.

Dialect reference: [MapleSyrup](https://github.com/saschanaz/MapleSyrup) explicitly implements per-channel tempo synchronization and conversion away from N notes and dotted L commands for MS2. The compiler uses named notes; per the user correction below, dotted L defaults are supported despite that reference implementation converting them away. Automated tests independently decode generated strings to compare musical timing, pitches, V values and tempo positions; native Electron tests verify window/clipboard behavior. No in-game MS2 playback validation has been performed.

Tie ordering: `&` belongs immediately before the continued note. A tempo boundary inside a held C emits `c4t150&c4`, never `c4&t150c4`. Note-bound tempo changes propagate across channels and instruments just like silent Instructions events.

Default-length compaction uses only L1–L64. MS2 accepts explicit `c128` and `r128`, but drops `l128`; `l128c` therefore cannot represent `c128`. One-unit notes, rests and tied continuations always retain their explicit 128 denominator. Dotted defaults such as `L1.` are valid and may compact repeated dotted durations: `l1.c` lasts 192 model units (a dotted whole note). Explicit lengths override the complete default, including its dot; `l1.c128` still lasts one unit. This output constraint does not change stored durations, editing grids or the shared-dialect importer. Character counts and sheet planning use the corrected output.

MS2MML export wraps generated non-empty channels as XML: channel 1 is `<melody>`, subsequent channels are numbered `<chord index="1">` through `<chord index="9">`. Same-pitch overlaps remain in their instrument and produce a warning. Export prompts before writing any instrument over the configurable character limit (default 10,000), offering a single file, synchronized parts, or cancellation. See SHEET_LIMITS.md.

Overlap warning definition (2026-09-07 correction): two notes must have the same start time, pitch and instrument. Different onsets during a sustained note do not qualify. Fixed-sound drum mapping does not change this source-note definition. Channel allocation still considers sounding durations; the active musical instrument has yellow boxes over intervals requiring more than ten simultaneous voices. Notes ending at a boundary are removed before counting notes starting there. The highlight follows edits and selection independently of manual MML snapshot updates; Instructions events do not count.
